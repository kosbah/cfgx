# Phase 4: Artifact Generators

## Goal

Implement `gen/artifacts` — a package that generates all non-Go artifacts from a
`*ir.SchemaIR`: `.env.example`, `config.example.yaml`, `config.schema.json`,
`docs/config.md`, and `docs/config.1` (man page fragment).

---

## Prerequisites

- Phase 1 complete: `internal/ir` types exist
- Phase 2 complete: parser exists (integration test)
- Read `docs/design/config-anatomy.md` — especially the sensitive, deprecated, and
  dependsOn sections; these have specific artifact representations

## Public API

Each generator has the same signature:

```go
package artifacts

// EnvExample generates a .env.example file from schema.
func EnvExample(schema *ir.SchemaIR) ([]byte, error)

// YAMLExample generates a config.example.yaml file from schema.
func YAMLExample(schema *ir.SchemaIR) ([]byte, error)

// JSONSchema generates a config.schema.json (JSON Schema draft-07) from schema.
func JSONSchema(schema *ir.SchemaIR) ([]byte, error)

// Markdown generates a config.md reference document from schema.
func Markdown(schema *ir.SchemaIR) ([]byte, error)

// ManPage generates a groff man page fragment (config.1) from schema.
func ManPage(schema *ir.SchemaIR, appName, version, date string) ([]byte, error)
```

No external dependencies. Use only `encoding/json`, `text/template`, `strings`, `bytes`.

## Generator specifications

### `EnvExample`

Format:

```sh
# ── General ──────────────────────────────────────────────────────────
# Human-readable application name
APP_NAME=myapp

# Enable debug logging; hot-reloadable via APP_DEBUG
APP_DEBUG=false

# ── Server ────────────────────────────────────────────────────────────
# HTTP port the server listens on
APP_PORT=8080

# ── Database ──────────────────────────────────────────────────────────
DB_HOST=localhost
DB_PORT=5432
DB_NAME=

# REQUIRED — sensitive, do not commit
DB_PASSWORD=

# ── DEPRECATED ───────────────────────────────────────────────────────
## DEPRECATED: use APP_NEW_FLAG instead
# APP_OLD_FLAG=
```

Rules:
- Section headers: derived from Tags; entries without tags go in an "Other" section
- Each entry preceded by a comment with its description (if set)
- Sensitive entries: empty value + `# REQUIRED — sensitive, do not commit`
- Deprecated entries: `## DEPRECATED: <message>` comment, entry commented out with `#`
- Entries without an Env: omit (comment noting "no env var; use config file")
- Default value: shown as the value (empty string for zero values)
- Computed entries: omit entirely (they have no env var)
- Ordering: tags order, then alphabetically within each tag group

---

### `YAMLExample`

Format:

```yaml
# cfgx example configuration
# Generated by cfgx. Update with your values.

# Human-readable application name
app-name: myapp

# Enable debug logging
app-debug: false

# ── Database ─────────────────────────────────────────────────────────
db:
  host: localhost
  port: 5432
  # Database name (required)
  name: ""
  # sensitive — do not commit this value
  password: ""
  # dsn is computed; do not set manually
```

Rules:
- Nested objects use YAML block structure (indented)
- Computed entries: comment saying "computed; do not set manually"
- Sensitive entries: empty string + `# sensitive — do not commit this value`
- Required entries: comment `# (required)`
- Deprecated entries: comment `# DEPRECATED: <message>`
- Use `app-name` (kebab-case) as keys, matching the entry ID
- Boolean defaults: `true`/`false` (not `yes`/`no`)
- Section comments using `# ── Tag Name ──────`

### `JSONSchema`

Produce a JSON Schema draft-07 document. The root object is of type `"object"`.

Type mapping:

| EntryType | JSON Schema type |
|---|---|
| `string`, `duration` | `"string"` |
| `int` | `"integer"` |
| `float64` | `"number"` |
| `bool` | `"boolean"` |
| `list` | `"array"` |
| `object` | `"object"` |
| `computed` | omit (not user-settable) |

Property rules:
- `"description"`: from `EntryIR.Description`
- `"default"`: from `EntryIR.Default` (if set)
- `"writeOnly": true` for Sensitive entries
- `"deprecated": true` for Deprecated entries (draft-07 extension)
- `"x-env"`: `EntryIR.Env` (custom extension)
- `"x-flag"`: `EntryIR.FlagLong` (custom extension)
- `"required"` array: all Required entries at each level

Built-in validator → JSON Schema keyword mapping:

| Validator | JSON Schema keyword |
|---|---|
| `email` | `"format": "email"` |
| `url` | `"format": "uri"` |
| `port` | `"minimum": 1, "maximum": 65535` |
| `port_range` | `"minimum": min, "maximum": max` |
| `base64` | `"contentEncoding": "base64"` |
| `regex` | `"pattern": pattern` |
| `duration` | `"pattern": "^-?\\d+(\\.\\d+)?(ns|us|µs|ms|s|m|h)$"` |
| `semver` | `"pattern": "^v?\\d+\\.\\d+\\.\\d+"` |
| `enum` | `"enum": [...]` |
| `range` | `"minimum": min, "maximum": max` |

The JSON must be indented with 2 spaces. Use `encoding/json` with `json.MarshalIndent`.

### `Markdown`

Format:

```markdown
# Configuration Reference

Generated by cfgx. Do not edit manually.

---

## General

| Name | Env | Flag | Type | Default | Required | Description |
|------|-----|------|------|---------|----------|-------------|
| `app-name` | `APP_NAME` | — | string | `myapp` | No | Human-readable application name |
| `debug` | `APP_DEBUG` | `--debug` | bool | `false` | No | Enable debug logging (🔄 hot-reload) |

## Database

| Name | Env | Flag | Type | Default | Required | Description |
|------|-----|------|------|---------|----------|-------------|
| `db.host` | `DB_HOST` | — | string | `localhost` | No | |
| `db.password` | `DB_PASSWORD` | — | string 🔒 | — | **Yes** | |

## Deprecated

| Name | Env | Type | Deprecation message |
|------|-----|------|---------------------|
| ~~`old-flag`~~ | `APP_OLD_FLAG` | string | use --new-flag instead |
```

Rules:
- Group by Tags; entries with no tags go in "Other"
- Deprecated entries in a separate "Deprecated" section at the bottom, struck-through
- Sensitive: type column shows `string 🔒`
- IsLive: description has `(🔄 hot-reload)` appended
- Computed entries: show type as `computed` with description `derived from siblings`
- MutuallyExclusive constraints shown as a note at the end

### `ManPage`

Produce a groff fragment suitable for inclusion in a `.1` man page.

```groff
.SH CONFIGURATION
.TP
.B APP_NAME
Human-readable application name. Default: myapp.
.TP
.B APP_PORT
HTTP port the server listens on. Default: 8080. Range: 1024\-65535.
.TP
.B DB_PASSWORD
Database password.
.B REQUIRED. SENSITIVE.
```

Rules:
- Only entries with an Env are included
- Sensitive: append `\fBREQUIRED. SENSITIVE.\fR`
- Required: append `\fBREQUIRED.\fR`
- Default: append `Default: value.`
- Deprecated: wrap in `.B "DEPRECATED: message"`
- Computed entries: omit

## Test requirements

All tests use golden files. Pattern:

```go
func TestEnvExample(t *testing.T) {
    ir := loadIR(t, "testdata/golden/full_ir.json")
    got, err := EnvExample(ir)
    require.NoError(t, err)
    compareGolden(t, "testdata/golden/env.example", got)
}
```

Use a `-update` flag to regenerate golden files.

Create golden files for:
1. Full schema (all features exercised)
2. Minimal schema (one entry)
3. Nested object schema
4. Schema with deprecated entries
